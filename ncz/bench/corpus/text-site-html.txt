# ncz — neural lossless compressor

A small, self-contained **context-mixing** compressor (PAQ/lpaq lineage) with
**bit-exact, full-quality retrieval**. No GPU, no dependencies, stdlib only.

## What it actually is (no hype)

- **Neural:** a logistic *mixer* — a single-layer neural net trained online by
  gradient descent, **one step per bit** — combines predictions from several
  byte-context models. No pretrained weights; the net adapts to *your* data as
  it streams.
- **Lossless ("full quality retrieval"):** the predictor → **binary range
  coder** pipeline is all integer / fixed-point, so encoder and decoder compute
  byte-identical probabilities. The decoder replays the exact same model updates
  in the same order ⇒ reconstruction is bit-exact. Verified by round-trip on
  every run (`ncz test`).
- **The catch nobody markets:** neural lossless compression is **slow**. This
  pure-Python reference runs at **~70 kB/s**. That is fine for files, *not* for
  "compress my whole disk in the background." Ratio-for-time is the whole trade.

## How it works

```
bytes ─▶ context models (order 0,1,2,3,4,6 + partial byte)
            │  each outputs P(next bit = 1), 12-bit fixed point
            ▼
        stretch()  (logit space)
            │
            ▼
        logistic mixer  ◀── online gradient update (the neuron)
            │  squash() back to a probability p
            ▼
        binary range coder ─▶ compressed bits
```

Decoding runs the identical model; each decoded bit feeds the *same* update, so
the two sides never diverge. That mirror-update property is what makes it
lossless without storing any model.

## Usage

```bash
# single file
python3 ncz.py compress   bigfile      bigfile.ncz
python3 ncz.py decompress bigfile.ncz  bigfile.out

# a directory / "disk" — pipe through tar (stdin/stdout = "-")
tar cf - mydir | python3 ncz.py compress - mydir.tar.ncz
python3 ncz.py decompress mydir.tar.ncz - | tar xf -

# self-check: round-trip + ratio vs gzip/bz2/lzma
python3 ncz.py test [file]
```

## Measured (this machine)

Best ratio per row in **bold**. ncz v2 wins every corpus here.

| corpus                | **ncz v2** | gzip -9 | bz2 -9 | lzma   | lossless |
|-----------------------|-----------|---------|--------|--------|----------|
| dict words (30 KB)    | **4.14x** | 3.27x   | 3.14x  | 3.61x  | ✅       |
| mixed text (60 KB)    | **4.02x** | 3.15x   | 2.97x  | 3.57x  | ✅       |
| source code (15 KB)   | **3.41x** | 3.04x   | 3.10x  | 3.11x  | ✅       |

v2 added the match model (LZP), adaptive-rate StateMaps, a context-gated mixer,
and two SSE/APM stages — which is what moved it ahead of lzma. Cost: ~27 kB/s
(down from ~70 in v1) because there's more model to run per bit.

## Upgrade path (remaining wins, in order)

1. **Word / sparse / indirect contexts:** model whole words and skip-gram
   contexts, not just byte n-grams. Big on natural-language text.
2. **2-layer mixer:** a second mixing layer with context-selected weight sets.
3. **Bit-history states + run map:** replace the direct StateMap counter with a
   nonstationary bit-history state machine (full PAQ). A few % more.
4. **Speed:** bit-serial Python is the bottleneck. Real usability = port the hot
   loop (predict + update + coder) to Rust/C via ctypes/cffi. 100–1000× feasible.
   Vectorizing in numpy does *not* help — the loop is inherently serial.

## Why integer math, not a float net

Floating-point results can differ across builds/platforms. A single different
bit in the predicted probability desyncs the range coder and corrupts everything
downstream. Integer fixed-point is deterministic ⇒ the lossless guarantee holds
regardless of where you decompress.
